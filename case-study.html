Case Study 1

RISC vs. CISC • Choosing a Processor

Comparing two processor design styles and picking the better one for a battery-powered embedded device (COA 25CST-238).

Scenario

A technology company has built two computing systems, one on a RISC architecture and one on a CISC architecture. The team now has to choose an instruction-set design for a low-power embedded device. My job is to compare the two and justify which one fits this use case better.

Part 1 — Case Study Questions

RISC (Reduced Instruction Set Computer) uses a small set of simple instructions, and most of them finish in about one clock cycle. Only LOAD and STORE instructions talk to memory; everything else works on registers. Examples: ARM, RISC-V, MIPS.

CISC (Complex Instruction Set Computer) has a large set of instructions, and some of them do several jobs at once, for example reading from memory, calculating, and writing back in a single instruction. These can take several cycles. Examples: Intel x86, VAX, Motorola 68000.

If every instruction has the same size (32 bits in classic MIPS and ARM), the processor already knows where the next instruction starts without looking at the current one. So fetching can happen ahead of time, the decoder stays simple, and the pipeline does not stall while it works out instruction boundaries.

The price is slightly bigger programs, because even a simple operation takes the full instruction width.

The more varied and complex the instructions are, the harder they are to decode. In x86, instructions can be anywhere from 1 to 15 bytes long and may have prefixes and optional fields, so the decoder first has to find out the length before it can even locate the next instruction. That needs more logic, more transistors and more power.

RISC decoding is mostly just reading fixed bit fields (opcode, registers, immediate value), which is quick and cheap. The saved chip area can then be used for more registers or cache.

RISC keeps addressing modes few: register, immediate, and base-plus-offset. Only load/store instructions use memory addressing.

CISC offers many modes: direct, indirect, indexed, base + index × scale + displacement, even memory-to-memory, and most instructions are allowed to use them.

So CISC is more flexible for the programmer or compiler, while RISC is easier to build and pipeline.

Yes. The main reason is code density. One CISC instruction can replace several RISC instructions, so the program is smaller and needs less instruction-fetch bandwidth. When memory is slow or the cache is small, this can make CISC faster.

Also, modern x86 chips break complex instructions into RISC-like micro-operations internally, so they get the benefits of both styles.

Part 3 — Example Instruction Sequences

Example 1: counter = counter + 1

CISC (x86) – 1 instruction

ADD DWORD PTR [counter], 1

RISC (ARM) – 3 instructions

LDR  R1, [R0]      ; load counter
ADD  R1, R1, #1    ; add 1
STR  R1, [R0]      ; store result

CISC reads memory, adds and writes back in one go. RISC splits it into three simple steps that are easy to decode and pipeline.

Example 2: Copying a block of bytes

CISC (x86) – 1 instruction

REP MOVSB

RISC (ARM) – a short loop

loop: LDRB R2, [R0], #1   ; load byte, move pointer
      STRB R2, [R1], #1   ; store byte, move pointer
      SUBS R3, R3, #1     ; decrement count
      BNE  loop           ; repeat until zero

CISC gives shorter code; RISC gives simpler and more predictable hardware.

Part 4 — Recommendation for a Battery-Powered Embedded Device

I recommend a RISC architecture, such as ARM Cortex-M or RISC-V.

  1. Lower power use. A simple decoder and fixed-length instructions mean fewer transistors switching, so less energy per instruction. On a battery, this matters most.
  2. Smaller, cheaper chip. Less control logic means a smaller die, lower cost and less heat, so no fan or heat sink is needed.
  3. Predictable timing. Sensors and controllers often have real-time deadlines. Mostly single-cycle instructions make execution time easy to estimate.
  4. Efficient pipelining. Uniform instructions keep the pipeline full, so the work gets done at a low clock speed, which saves more power.
  5. Strong ecosystem. ARM and RISC-V have wide toolchain, library and microcontroller support for low-power designs.

Trade-off: RISC programs are larger. But flash memory is cheap, and compressed instruction sets (ARM Thumb, RISC-V "C" extension) shrink the gap a lot. CISC's strengths, like raw speed on complex workloads, matter less here than energy efficiency.

Conclusion: CISC tries to do more per instruction, while RISC tries to do each instruction cheaply and quickly. For a low-power embedded device, the simplicity, efficiency and predictability of RISC make it the better choice.
